Run C online in your browser

Execflow compiles your C program with clang and runs it inside your browser tab, so it needs no compiler on your computer and no account. scanf waits for you to type, compiler errors point at their line, and the common ones, crashes included, come with an explanation in plain words.

Getting started

  1. Open the editor and make a file whose name ends in .c.
  2. The first time, Output offers the compiler as a one-time download. In Execflow's words: “”
  3. Press Run. Execflow compiles, links and runs the program; the run log shows how long the build and the run took.
  4. When the program calls scanf, type into the field in Output and press Enter, or put the input in the Input box before you run.

Examples, with what they really printed

Every program here was compiled and run in Execflow, and its output is copied exactly, typed input included. Open in Execflow loads it into the editor; nothing compiles or runs until you press Run.

Reading numbers with scanf

scanf("%d %d", &a, &b) reads two whole numbers separated by a space. The & gives scanf the address of each variable, so it can store into it. Dividing two ints would drop the fraction, so one of them is cast to double first.

An array and a loop

Seven temperatures in an array, one pass of a for loop to add them up and remember where the highest one is. Indexes run from 0 to 6, so the program adds 1 when it prints the day.

Pointers: swapping two variables

C passes arguments by value, so a function can't change the caller's variables unless it gets their addresses. swap receives two pointers and changes what they point to.

A compiler error: the missing semicolon

One missing ; at the end of line 4. clang reports it where it noticed, and Execflow adds what the message means.

A crash: an index far outside the array

The array has 5 places, but nothing stops the program from using the number typed in as an index. On your own computer this is usually a segmentation fault; here the program is stopped the same way, and Execflow says what usually causes it.

Which compiler and standard?

__STDC_VERSION__ is 201112 for C11 (gnu11 is C11 with GNU extensions). Pointers are 4 bytes because the program is compiled to 32-bit WebAssembly.

The compiler and its settings

  • clang 8.0.1 and lld, compiled to WebAssembly (the wasm-clang project), with the wasi-libc C library. They run in a worker in your page; your code is never sent to a server to be compiled.
  • The defaults: -std=gnu11 -O2 -Wall. Warnings show next to the code without stopping the build.
  • In Settings you can pick the C standard (c99, c11, c17, gnu11 or gnu17), the optimisation level (-O0, -O1 or -O2), and turn on -Wextra.
  • Memory: a program can use up to 256 MB.

Limits

A program is stopped after 15 seconds of running, or when it has printed 524,288 characters, so an endless loop can't freeze the page; time spent waiting for input doesn't count. Settings changes both. A single compile step that takes longer than 30 seconds is stopped too.

C programs can't reach the network or open windows: they read from the keyboard and print text, which is what course exercises do.

Questions

Is this GCC?

No, it is clang 8, the C compiler of the LLVM project. Both follow the C standard; their messages are worded differently, and Execflow explains the common ones in plain words either way.

Does it work offline?

Yes, once the compiler has been downloaded. The 19.6 MB download happens once per browser, when you first run C or C++; after that, programs compile and run without a connection.

Do I need to sign up?

No. Your files are kept in your browser. Connecting GitHub, to sync files to your own private repository, is optional.

Is my code private?

Your code is compiled and run on your computer. A code link carries the program inside the link, after #code=; browsers never send that part to a server, and opening the link shows the code first and runs nothing. The privacy page explains what Execflow keeps and sends.

Why does a wrong index sometimes not crash?

C doesn't check indexes. A small mistake often writes over another variable instead, and with -O2 the compiler can remove code whose result is never used. A crash only happens when the address is outside the program's memory altogether, as in the example above.
