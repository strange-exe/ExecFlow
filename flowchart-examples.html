How to read these flowcharts

A flowchart shows the order in which a program's steps run, and the points where it chooses between two paths. Drawn before you write the code, it lets you check the logic; drawn after, it explains the code to someone else. The charts on this page use four shapes:

  • Rounded ends: Start, and End. In C the End shows the return that ends the program, as End: return 0.
  • Slanted boxes: input or output. That is scanf and printf in C, and input and print in Python. A line such as n = int(input(...)) counts as input.
  • Rectangles: a step that works something out or stores it, such as fact = fact * i. Up to three simple statements in a row share one box.
  • Diamonds: a decision, with one arrow labelled Yes and one labelled No. A loop is a decision too: its Yes arrow runs through the loop's body and back up to the diamond, and its No arrow leaves the loop.

Start at Start, follow the arrows, and at each diamond take the arrow that matches the answer. Under every chart, Steps as text gives the same chart as a numbered list. To draw the chart of your own program, see Flowchart from code.

1. Largest of three numbers

Read three whole numbers and print the largest. Some of them may be equal; the largest value is still printed once.

  1. Read a, b and c.
  2. If a is greater than or equal to both b and c, the largest is a.
  3. Otherwise the largest is b or c: if b is greater than or equal to c, it is b.
  4. Otherwise it is c. Print the largest.

2. Even or odd

Read a whole number and say whether it is even or odd. A number is even when it divides by 2 with nothing left over, so 0 is even, and so is -4.

  1. Read n.
  2. Work out the remainder of n divided by 2 (n % 2).
  3. If the remainder is 0, n is even; otherwise it is odd. Print which.

The flowchart is drawn from the Python program. Python's top level has no main, so ExecFlow names its chart Program.

The same steps in C, run with a negative number:

A common mistake: testing n % 2 == 1 for odd. In C the remainder takes the sign of the number being divided, so -7 % 2 is -1, not 1, and a negative odd number comes out even:

Testing n % 2 == 0, as above, is right for every int. In Python -7 % 2 is 1, so this mistake shows only in C.

3. Factorial

The factorial of n, written n!, is 1 × 2 × ... × n, so 5! is 120. By definition 0! is 1, and a negative number has no factorial.

  1. Read n. If it is negative, say there is no factorial and stop.
  2. Set fact to 1.
  3. For each i from 1 to n, multiply fact by i.
  4. Print fact.

The flowchart is drawn from the C program. A C for loop is drawn in its three parts: the start (i = 1), the test (the diamond) and the update (i++) after the body.

The same steps in Python, run with 0: the loop runs zero times, so fact stays 1, which is the right answer. Python's whole numbers have no size limit, so the calculation works for large n too; printing a result longer than 4,300 digits (1559! and up) needs sys.set_int_max_str_digits().

A common mistake: keeping the result in an int. On ExecFlow's compiler, as on most today, an int holds values up to 2,147,483,647, so 12! (479,001,600) is the last factorial that fits. 13! is 6,227,020,800, and the program prints a wrong number without any error:

Overflowing a signed int is undefined behaviour in C, so another compiler may print something else. The program above uses long long, which holds every factorial up to 20! (2,432,902,008,176,640,000); 21! does not fit in it either.

4. Prime number check

A prime is a whole number greater than 1 whose only divisors are 1 and itself. So 0, 1 and every negative number are not prime, and 2 is the only even prime.

  1. Read n. If it is less than 2, it is not prime.
  2. Try each divisor i, starting at 2, for as long as i * i is at most n.
  3. If n divides by i with nothing left over, n is not prime: stop trying.
  4. If no divisor was found, n is prime. Print the answer.

Stopping at i * i <= n is enough: if n has a divisor larger than its square root, the number it pairs with is smaller than the square root, and the loop tries that one. For 97 that means trying 2 to 9 instead of 2 to 96.

The flowchart is drawn from the Python program. The break is the arrow from is_prime = False straight to the decision after the loop.

The same steps in C, where the test and the update fit in one for line. In C, i * i is an int too, so for a prime above 2,147,395,599, close to the int limit, it would overflow; make i a long long if you need numbers that large.

A common mistake: getting the loop's end wrong. range(2, n + 1) includes n itself, and every number divides by itself, so every number comes out not prime:

range(2, n) stops before n, which fixes it; the square-root test above stops much sooner.

5. Fibonacci series

Each term is the sum of the two before it: 0, 1, 1, 2, 3, 5, 8 and so on. These programs start at 0 and 1 and print the first n terms.

  1. Read n, the number of terms.
  2. Set a to 0 and b to 1.
  3. Repeat n times: print a, then set next to a + b, a to b, and b to next.

For n of 0 or less the loop doesn't run, and the program prints only an empty line.

The flowchart is drawn from the C program. The three statements that move the series on share one box.

A long long is big enough for 91 terms in this C program, which works out two terms ahead of the one it prints: for 92 terms it would compute the 94th, which overflows. Python's numbers have no such limit:

A common mistake: an off-by-one loop. Starting at i = 0 and keeping i <= n runs the loop n + 1 times, so asking for 5 terms prints 6:

Count the runs before you trust a loop: from 1 with i <= n, or from 0 with i < n, both run n times.

6. Sum of digits

Add up the digits of a whole number: for 4721 that is 4 + 7 + 2 + 1 = 14. The sign is ignored, so -305 gives 8, and 0 gives 0.

  1. Read n. If it is negative, make it positive.
  2. Set total to 0.
  3. While n is greater than 0: add its last digit (n % 10) to total, then drop that digit by dividing n by 10 and keeping the whole part.
  4. Print total.

The flowchart is drawn from the Python program. The loop's two statements share one box.

The same steps in C, where n / 10 between two ints already keeps only the whole part. One edge: n = -n doesn't work for the most negative int, -2,147,483,648, because 2,147,483,648 doesn't fit in an int.

A common mistake: writing / instead of // in Python. There, / always gives a decimal number, so 4721 becomes 472.1, then 47.21, and so on. The loop keeps adding the remainders of those fractions until n is so small it counts as 0:

7. Reverse a number

Write the digits of a number in the opposite order: 1234 becomes 4321. Zeros at the end are lost, because a number can't start with zeros, so 1200 gives 21. These programs expect 0 or a positive number.

  1. Read n, and keep a copy of it as original.
  2. Set reverse to 0.
  3. While n is greater than 0: take its last digit (n % 10), add it to the end of reverse (reverse * 10 + digit), and drop it from n (n / 10 in C, n // 10 in Python).
  4. Print original and reverse.

The flowchart is drawn from the C program.

In C the reverse has to fit in an int too: 1,999,999,999 is a valid int, but its reverse, 9,999,999,991, is not. The same steps in Python, run with 1200:

8. Simple interest

Simple interest is P × R × T / 100, for a principal P, a rate R in percent per year and a time T in years. Rate and time can have fractions, so the programs read decimal numbers. For 5,000 at 7.5% for 3 years: 5000 × 7.5 × 3 / 100 = 1,125.

  1. Read P, R and T.
  2. Work out SI = P × R × T / 100.
  3. Print SI.

The flowchart is drawn from the Python program. There is no decision and no loop, so the chart is a straight line: three inputs, one step, one output.

The same steps in C. In its prompt, %% prints one % sign, because printf reads a single % as the start of a format such as %f.

A common mistake: leaving out float(). input() always returns text, so p * r tries to multiply two pieces of text, and Python stops with a TypeError:

Convert each input with float(), or int() for whole numbers, before doing arithmetic with it.
