Privacy

What ExecFlow keeps, where it goes, and how to remove it.

Last updated 31 October 2026

Read the Terms

The short version

  • Your code runs in your browser. It is never sent to a ExecFlow server to be run.
  • Your files stay in this browser unless you connect GitHub or share one. Synced files go only to the GitHub repository you choose; a file you share goes wherever you send its link.
  • ExecFlow has no accounts of its own, no cookies and no ads. The only analytics are Cloudflare's page-load measurements, described under Hosting.
  • Settings has a button that removes everything ExecFlow keeps in this browser.

1 Who runs ExecFlow

ExecFlow is made and run by Abhinesh. Questions about this page go to the project's GitHub issues. Issues are public, so don't put code, tokens or anything personal in one.

2 What stays in your browser

ExecFlow keeps these in your browser's own storage for this site. They don't leave your computer unless a later section says so.

  • Your files and folders, the files you have open, and the arguments you set for a program.
  • Your settings: theme, code font size, print and image options, and the size of the panels.
  • The version you last opened, so ExecFlow can tell you once what's new after an update.
  • A recovery copy of unsaved typing, kept if the page closes before it is saved, and removed once you come back.
  • The Input box text, for as long as the tab is open.
  • The tools ExecFlow downloads to run and chart code (Python, the C and C++ compiler, the flowchart parser), so they don't download again. They hold none of your files.

Your browser may clear this storage to free space. Settings has "Protect local data" to ask it not to.

3 Running and charting code

Python, C and C++ programs run inside your browser. Flowcharts are drawn there too. Exported images, printouts and PDFs are made on your computer.

4 If you connect GitHub

GitHub is optional. If you connect it:

  • Your browser talks to GitHub directly. ExecFlow sends your files, their folder paths and a commit message to the repository you picked. Each commit message names the files that changed and ends with the browser and system you used, for example "From: Chrome on Windows (ExecFlow)".
  • "Sign in with GitHub" asks GitHub for access to the repositories you choose when you install the ExecFlow app (their files and basic details), and, only if you turn on sharing by secret gist, to your gists. A personal access token gets exactly what you gave it on GitHub.
  • Your GitHub token is kept in memory and forgotten when the tab closes. If you tick "Remember on this device" (off unless you choose it), it is stored in this browser, encrypted.
  • ExecFlow reads your GitHub user name to show who is signed in, and the list of repositories you gave it.

What happens to data on GitHub is covered by GitHub's privacy statement.

4.1 The sign-in step on ExecFlow's server

Signing in with GitHub needs one secret that can't be in a web page, so a small server function on ExecFlow's site finishes that step. It receives the one-time code from GitHub, and later your token when it is renewed or when you disconnect, passes them to GitHub, and returns GitHub's answer. It doesn't store or log them. Signing in with a personal access token doesn't use it.

4.2 Share links

  • A code link carries a copy of one file, or of the files you ticked in Choose files, inside the link itself, after the #. Browsers never send that part of a link to a server, so the code isn't uploaded or stored anywhere: anyone who has the link can read it, for as long as they have it. Opening one shows the code first and adds it to your files only when you choose (a shared folder as a new folder).
  • A short link keeps the same copy on ExecFlow's server instead, locked (encrypted) in your browser before it is sent. The server stores only the locked bytes and the date they expire, after 1, 30 or 90 days as you choose; then they are deleted. The key that unlocks them is the part of the link after the #, which never reaches the server, so ExecFlow can't read your code. Anyone who has the full link can read it until it expires, and it can't be deleted sooner. To limit misuse, the server counts the short links made from each network for an hour, by a scrambled (hashed) form of its IP address that is never stored with the link.
  • A link to the file in your repository uploads nothing new. Only people who can see the repository can open it.
  • A secret gist puts a copy of one file on your GitHub account. Anyone who has the link can read it, without signing in. ExecFlow never deletes gists: delete it on GitHub when you no longer want it shared.

5 Hosting

The site is served by Cloudflare. Like any web host, Cloudflare receives your IP address and the details of each request so it can deliver the page, under Cloudflare's privacy policy.

ExecFlow also uses Cloudflare Web Analytics, which Cloudflare adds to each page. When a page loads and when you leave it, a small Cloudflare script reports to Cloudflare, through this site's address, how long the page took to load and which page it was (without anything after a "?" in the address). Cloudflare says it doesn't collect visitors' personal data. It never sees your code, your files or what you type. ExecFlow's own code adds no other tracking or advertising, and sets no cookies.

6 Removing your data

  • Settings, "Sign out and clear this computer" removes every file, setting and saved token ExecFlow keeps in this browser, then reloads the page. Files that aren't synced to GitHub are lost, so export them first if you need them.
  • Settings, "Disconnect GitHub" stops syncing and forgets your token. If you signed in with GitHub, it also asks GitHub to cancel the sign-in. A personal access token stays valid on GitHub until it expires or you delete it there.
  • To be sure no access is left, remove ExecFlow on GitHub under Settings, Applications, Authorized GitHub Apps (how), and delete any personal access token you made for it.
  • Files in your repository, their commits and any secret gists are yours on GitHub: delete them there.
  • A short link's locked copy is deleted from ExecFlow's server when the link expires.
  • The downloaded tools stay in the browser's cache until you clear this site's data in your browser's settings.

7 Changes to this page

If ExecFlow starts keeping or sending anything new, this page changes first, with a new date at the top.
