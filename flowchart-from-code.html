Turn Python, C or C++ code into a flowchart

Write or paste a program in CodeEditor, open the Flowchart tab, and every decision, loop and early return of the function you pick becomes a box in the standard flowchart shapes. It is drawn in your browser from the code itself, so the chart follows the code's structure, statement by statement.

From code to chart in four steps

  1. Open the editor and create a file ending in .py, .c or .cpp, or paste your code into one.
  2. Open the Flowchart tab next to Output. The chart of the program's entry point appears: main in C and C++, and in Python the file's top level, called Program.
  3. Pick another function from the Function menu: each function, and in Python each method, has a chart of its own.
  4. Click a box to jump to its lines in the code, or open Steps as text to read the same chart as a numbered list. Export saves it as a PNG or an SVG.

The chart follows the code as you type. You don't need to run the program first, and the program doesn't need to be finished: the parser draws what it can read.

Worked examples

Each chart below is the one CodeEditor drew for the code beside it, saved with its own SVG export and shown here in this page's colours. The output under each program is what it printed when it ran in CodeEditor. Open in CodeEditor shows the program in CodeEditor as a preview first. Add to my files puts it in the editor, where you can change the code and watch the chart follow; nothing runs until you press Run.

A loop: adding up 1 to 5

A for loop is drawn as a decision: is there another value of n? The Yes arrow goes into the loop's body and back up to the decision; the No arrow leaves the loop for the print, which is drawn as input or output. Python's range(1, 6) stops before 6, which is why the total is 15.

If and else: pass or fail

The diamond asks the if condition. Yes leads to the first printf, No to the else branch, and both meet again before return 0, the End. scanf is input, so it gets the same slanted shape as printf.

A function with an early return

This is the chart of the function find, picked from the Function menu. It has two ends: the return i inside the loop leaves as soon as the item is found, and return -1 runs only when the loop has checked every item. Charts like this make an early return easy to see, where in the code it is one indented line.

Nested loops: a multiplication table

The inner loop is a second decision inside the first one's Yes branch. A C or C++ for loop is drawn in its three parts: the start (int col = 1), the test (the diamond) and the update (col++) after the body. When the inner test says No, the program prints the line break, moves to the next row and goes back to the outer test.

What each shape means

The shapes are the standard flowchart symbols of ISO 5807. Each kind also has its own colour, but the shape and the words always say what it is.

  • Rounded ends (terminators): Start, and every End. A return, raise or throw is an End that shows its code, like End: return -1.
  • Diamonds (decisions): an if, elif, while, for or do test, with its arrows labelled Yes and No. A C or C++ switch fans out into one column per case, each labelled with its case.
  • Slanted boxes (input or output): print and input in Python; printf, scanf, puts, putchar, gets, fgets and getchar in C; those and getline, std::cout and std::cin in C++.
  • Boxes with side bars (calls): a call to one of your own functions, which has a chart of its own.
  • Rectangles (steps): everything else. Up to three simple statements in a row share one box, so a chart stays readable.
  • Small circles (connectors): where a loop with no test comes back to, and both ends of a C goto, named after its label.

A box the program can never reach, such as code after a return, is marked never reached.

Export as PNG or SVG

The Export button in the Flowchart tab offers Download PNG and Download SVG, and Copy image in browsers that can copy images. Under them you choose the colours: Print-safe light, dark ink on white (the default, good for printing and for documents), or Match the editor, the colours of your theme.

A PNG is drawn at twice the chart's size for sharp printing; a chart too big for the browser to draw at that size is saved smaller, and CodeEditor says so. An SVG stays sharp at any size and can be opened in drawing programs. Every export has a footer line with the file's name and the function it shows. The file is named after both, like find-py-find-flowchart.svg.

What is not drawn box by box

Some statements become one box with the note shown as one step, so the chart stays honest about what it leaves out. For example:

  • In Python: try, with and match blocks, a function or class defined inside another, a line that contains a lambda, and another expression that spans several lines.
  • In C and C++: try blocks (C++), preprocessor lines such as #ifdef inside a function, a statement that spans several lines, and a case label inside a block or loop within its switch.

Definitions are not steps of the code around them: the chart of a Python file's top level skips its def blocks, and each function gets a chart of its own. A function with more than 400 boxes, or nested more than 40 levels deep, is too big to draw; CodeEditor says so and you can pick a smaller function.

How the chart is made, and why it matters

CodeEditor reads your code with a parser (tree-sitter, the same kind of parser code editors use to colour code) and builds the chart from the program's structure. That has three consequences you can rely on:

  • The same code always gives the same chart. There is no AI model guessing at it, so there is nothing to double-check against the code: every box is a statement of it, and clicking the box shows which.
  • Your code stays on your computer. The chart is drawn by a worker in your browser. The only thing it downloads is the parser for the language, from this site, the first time you open a chart: about 0.7 MB for Python, 0.8 MB for C and 3.6 MB for C++. After that it is kept in the browser, so later charts don't download it again.
  • No daily limit, no sign-up. Draw as many charts as you like. The only limit is the size of one function's chart, above.

What the parser can't do is explain intent: the boxes show the code's own text, not a summary in words. If you need a chart in plain language for a report, export the SVG and edit the labels in a drawing program.

Questions

Does the code have to run without errors?

No. The chart comes from reading the code, not from running it. A program with a mistake still gets a chart, with a note above it such as Line 4 has a mistake, so this part of the chart may be incomplete. and a button that goes to that line. Running it is one click away, in the same window.

Can I draw a flowchart of one function?

Yes, that is how it works: every function has its own chart, picked from the Function menu. Calls to your other functions are boxes with side bars, so the chart of main stays short.

Does it work offline?

After your first visit the editor opens without a connection, and Python runs offline too. A language's flowchart parser is downloaded the first time you open a chart in that language, and kept in the browser after that.

Is my code sent anywhere?

Not to draw a chart. Files are kept in your browser unless you connect GitHub or share one. A shared code link carries the code after the # in the address, a part browsers never send to a server. The privacy page has the details.

What reads the code?

tree-sitter's grammars for Python, C and C++ (versions 0.25.0, 0.24.1 and 0.23.4), run by web-tree-sitter 0.27.1 in your browser. They are open source; the licences page lists them.
