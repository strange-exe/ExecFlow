What a loop looks like in a flowchart

Every loop has the same three parts, whatever the language:

  • A test, drawn as a diamond (a decision). Its two arrows are labelled Yes and No.
  • The body, the steps that repeat. The Yes arrow leads into it.
  • The way back: an arrow from the end of the body back up to the test. This arrow is what makes it a loop. Without it the chart is an if.

The No arrow leaves the loop and goes on to the next statement. Where the test sits decides the kind of loop. A for or while loop tests first, so its body can run zero times. A do-while loop runs its body first and tests after it, so the body always runs at least once.

The for loop: a multiplication table

Use a for loop when you know how many times to repeat: here, 10 lines of the table of a number you type.

A C for loop is drawn in its three parts. The start, int i = 1, is a box before the loop and runs once. The test, i <= 10, is the diamond. The update, i++, is a box at the end of the body, and the arrow back to the test leaves from it. When i reaches 11 the test says No and the program ends.

Python's for has no separate start and update: the diamond asks whether range(1, 11) has another value for i. A range stops before its end, so range(1, 11) gives 1 to 10, the same ten lines as the C program.

The while loop: adding up the digits of a number

Use a while loop when you don't know how many times it will run, only when to stop: here, when no digits are left.

The test n > 0 comes first, so for 0 the body never runs. Each pass adds the last digit (n % 10) and removes it from n; ExecFlow puts the two statements in one box. For 4096 the body runs four times and adds 6, 9, 0 and 4. In Python, n // 10 divides without a remainder, as n / 10 does for an int in C. Python's / would give 409.6.

The do-while loop: asking until the answer is valid

Use a do-while loop when the body must run before there is anything to test: here, the program can't check the number until it has asked for it. It asks again while the number is outside 1 to 10.

The diamond comes after the printf and the scanf, not before them. Its Yes arrow goes back up to the printf, and No goes on to You chose. Compare it with the while chart above, where the diamond is the first thing in the loop.

Python has no do-while loop. The usual way to write one is while True: with a break at the end of the body, when the answer is valid:

The chart shows the difference. The first diamond is True ?, at the top. ExecFlow draws it like any other test, with a No arrow, but True is never false, so that arrow is never taken. The real test is the second diamond: its Yes arrow is the break, which leaves the loop for the print, and its No arrow goes back up to ask again.

Nested loops: a triangle of stars

A loop inside a loop: the outer loop picks the row, the inner loop prints that row's stars. Row i has i stars.

The inner loop is a second diamond inside the Yes branch of the first, with its own arrow back. The inner loop runs to the end for every pass of the outer one, so the body with the star runs 1 + 2 + 3 + 4 = 10 times. When the inner test says No, the program ends the line, and in C moves i on with i++, then goes back to the outer test. In C, int j = 1 sits inside the outer loop, so j starts again at 1 on every row.

break and continue: adding up positive numbers

break leaves the loop at once. continue skips the rest of this pass and goes back to the test. This program adds up the numbers you type, skips negative ones with continue, and stops at 0 with break. The loop itself never ends on its own: while (1) in C and while True: in Python are always true.

break and continue are not boxes of their own; ExecFlow draws them as lines. The Yes arrow of n == 0 is the break: it runs out of the loop, past everything else, to the printf or print of the total. The Yes arrow of n < 0 is the continue: it goes back up to the loop's test and skips total = total + n. So -3 is never added, and the total is 5 + 8 = 13.

Common loop mistakes

Each program below has one mistake. The output is what it really printed in ExecFlow.

Off by one: < where you meant <=

Both programs were meant to print 1 to 10:

Both stop at 9. In C, i < 10 is false when i is 10, so the body never runs for 10: write i <= 10. In Python, range(1, 10) stops before 10: write range(1, 11). To check a loop, work out its first and its last pass by hand: what is the variable the first time the body runs, and the last time? With an array the same slip goes the other way: an array of 5 has the indexes 0 to 4, so its loop is for (i = 0; i < 5; i++), and i <= 5 reads one element past the end.

A loop that never ends

Both programs were meant to add up 1 to 5, but nothing in the loop changes i, so i <= 5 stays true. The Python one prints nothing while it loops:

While a program runs, the Run button turns into Stop (or press Ctrl+., Cmd+. on a Mac), so you can end it yourself. If you don't, ExecFlow stops it at the time limit of 15 seconds, as it did here, explains why under the output, and points to line 4 in Problems, the line the program was on when it stopped. Time spent waiting for your input doesn't count, and the limit can be changed in Settings.

The C one prints i on every pass, so it fills the output instead:

It printed i is still 1 again and again until it reached the output limit, in under a second; above are the last lines it printed. The fix for both is the line the loop is missing: i++; in C, i = i + 1 in Python, at the end of the body. In a flowchart, a loop that never ends is one where nothing in the body changes what the diamond tests.

Changing the loop variable inside a for loop

Both programs add 1 to i inside the body:

They don't agree. In C, i is an ordinary variable: the body adds 1 and the update i++ adds another, so every second number is skipped. In Python, the for loop takes the next value from range at the start of every pass, and that replaces whatever the body did to i. Either way, the loop no longer says what it does. To count in steps of 2, say so in the loop itself: i = i + 2 as the update in C, range(1, 7, 2) in Python.
