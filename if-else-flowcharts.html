If-else flowcharts: decisions in C and Python

A decision in a program is a question with two answers, Yes and No. In a flowchart it is a diamond, and each answer is an arrow to the steps that run for it. This page shows each kind of decision in C and in Python: a short program, the flowchart ExecFlow drew for it, and what it printed when it ran.

The diamond and its Yes and No arrows

ExecFlow draws the test of an if as a diamond holding the condition and a question mark, such as n < 0 ?. Two arrows leave it. The one labelled Yes is taken when the condition is true, the one labelled No when it is false. Yes is green and No is red, but the words are always there, so a chart printed in black and white reads the same. Below the diamond the two paths meet again, and the program carries on from there.

In C a condition is true when its value is not 0. In Python it is true for True, and also for a number that isn't 0 or a string or list that isn't empty.

Input and output (scanf, printf, input, print) are slanted boxes, and other steps are rectangles. A C chart has a box for the declaration, such as int n, and ends at return 0. A Python chart starts at the file's first line and ends at End. The flowchart from code guide lists every shape.

if: do something only when the condition is true

An if with no else has one branch. When the condition is false, nothing extra happens and the program goes straight on. This program prints how far a number is from zero: a negative number is made positive first.

In Python

The Yes arrow goes down through n = -n. The No arrow goes around it on the right, and both arrive at the line that prints. With -7 typed, the test says Yes, so 7 is printed. A positive number takes the No arrow and is printed as it is.

In C the lines that belong to the if are the ones between { and }; in Python they are the indented lines under it. The charts have the same shape. The C chart has two more boxes: the declaration int n, and a printf for the prompt, which Python's input() shows in the same step that reads the number.

if-else: one of two

With else, each arrow leads to a box of its own. Exactly one of the two branches runs, never both and never neither.

Yes leads to the left branch and No to the right one, and they meet before the end. With 15 typed, age >= 18 is false, so the No branch runs and works out 18 - age.

The else-if ladder: one of many

For more than two outcomes, chain the tests: else if in C, elif in Python. A grade calculator is the usual example.

In C

In Python

Each test is a diamond of its own on the No arrow of the one before it, so the chart steps down to the right like a ladder. The tests are asked in order and the first Yes wins; the tests after it are skipped. With 82, marks >= 90 says No, marks >= 75 says Yes, and the program prints Grade B without asking about 60 or 40. The last else takes whatever is left, here any mark below 40.

The order matters. The second test can be just marks >= 75, not marks >= 75 && marks < 90, because the first test has already sent every mark of 90 or more to Grade A. Put marks >= 40 first and every mark from 40 to 100 gets a D. These programs also don't check that the marks are between 0 and 100: a real one would test that first.

Nested if: a decision inside a decision

An if inside another if is a second question asked on one branch of the first. Leap years are the classic case. A year divisible by 4 is a leap year, except a year divisible by 100, which is a leap year only if it is also divisible by 400. So 2000 was a leap year and 1900 was not.

In C

In Python

Each inner diamond hangs from the Yes arrow of the one above it. For 1900 the C program answers Yes (divisible by 4), Yes (by 100) and No (not by 400): not a leap year. The Python program, given 2000, answers Yes three times.

The same rule fits in one condition: (year % 4 == 0 && year % 100 != 0) || year % 400 == 0 in C, with and and or in Python. The nested form is easier to follow on a chart, with one question per diamond.

switch in C: one value, many cases

A switch compares one value with a list of cases. Each case is a constant whole number or a character such as '+': not a string, and not a test such as marks >= 90. When no case matches, default runs.

A calculator with break

ExecFlow draws the switch as one diamond holding the value, op ?, with one column per case, each arrow labelled with its case. Every case ends with break, which leaves the switch, so each column goes straight down to return 0. With 8 * 5 typed, scanf reads 8 into a, * into op and 5 into b; op matches '*' and the program prints 40. There is no / case because dividing by 0 would need a check first.

The fall-through mistake: a missing break

Without break a case doesn't stop at its own lines: the program carries on into the next case's lines, and the next, to the end of the switch. So choosing 2 prints Coffee, then Juice, then No such drink. The chart shows it: each column's arrow runs into the top of the next column instead of down to the end. ExecFlow's compiler gave no warning for this program, so the chart and the output are where it shows.

The fix is a break; at the end of each case. Falling through is almost always a mistake; the common deliberate use is two cases sharing one body, written with nothing between them, as in case 'y': case 'Y':. ExecFlow draws such cases as one column labelled with both.

match in Python 3.10 and later

Python has no switch. Since Python 3.10 it has match, which compares a value with the pattern after each case; case _ matches anything, like default. ExecFlow runs , so match works there. On Python 3.9 or older it is a syntax error. There is no break: only the first matching case runs, and nothing falls through.

The calculator with match

The program runs, but the chart doesn't open the match up. ExecFlow draws the whole match as one box with the note shown as one step, as the chart beside it shows, so it can't show the branches. To see them as diamonds, write the same choice as an if and elif ladder (if op == "+":, then elif op == "-": and so on), which ExecFlow draws test by test, like the grade calculator above.

Common mistakes

= instead of == in C

A single = assigns. if (marks = 100) puts 100 into marks, and the condition's value is that 100, which isn't 0, so it is always true. With 35 typed, the program still takes the Yes branch and prints the full-marks line. clang compiles it with a warning, which ExecFlow lists under Problems and marks in the code:

Write == to compare: if (marks == 100).

The same line in Python

Python refuses it before anything runs: it reads the whole file first and stops at line 2, so the program never asks for the marks.

Comparing strings with == in C

In C, answer == "yes" doesn't compare the letters. It compares two addresses: where the array answer is in memory, and where the text "yes" is. They are different places, so the test is false even when you typed yes. clang warns:

In Python, == compares the text itself, so answer == "yes" works there.

The dangling else

The indentation says the else belongs to if (age >= 18), but C ignores indentation. Without braces, an else belongs to the nearest if before it that has no else, here if (ticket == 1). So a 15-year-old with a ticket gets no message at all. The chart shows where the else really went: it is the No arrow of the second diamond, and the first diamond's No arrow goes straight to return 0. clang warns:

Put braces around the inner if, as in if (age >= 18) { if (ticket == 1) ... } else ..., and the else belongs to the outer one. Python has no dangling else: an else belongs to the if at the same indentation.
